# ほじほじくんのフルーツキャッチ

3歳のお子さま向けの、減点・ゲームオーバーのないフルーツ集めゲームです。必要なものはブラウザだけ。外部API・広告・ログイン・ライブラリは使っていません。

## ファイル

```text
fruit-catch/
  index.html       5つの画面
  style.css        色・配置・アニメーション・スマホ対応
  script.js        ゲームのルール・操作・保存・音
  assets/
    orange.svg など  果物15種類の画像
    character.svg  キャラクターの元のSVG
    basket.svg     カゴ
    audio/         自分で録音した音声の置き場所
  README.md        この説明書
  TEST-RESULTS.md   動作確認の結果
```

## PCで今すぐ遊ぶ

1. ZIPをダウンロードした場合は、右クリックして「すべて展開」してください。
2. `fruit-catch` フォルダの `index.html` をChromeやEdgeで開きます。
3. 初回は「スタート」→遊び方→「スタート」で始まります。
4. ゲーム画面でマウスを左右に動かすとカゴが移動します。左右の矢印キーも使えます。

音は最初はオンです。「スタート」を押すと、ずんだもんの音声が有効になります。「おと：オン」でオフにできます。

ファイルを直接開く方法でも遊べますが、保存の扱いはブラウザにより異なります。長く図鑑を集める場合は、次のGitHub Pagesで公開した同じURLを使う方法がおすすめです。ファイルの場所や公開先が変わると、前の図鑑は引き継がれません。

## GitHub Pagesで公開する

このゲームの公開先は https://dbz0gt3gokuu5-arch.github.io/hojihoji-fruit-catch/ です。以下は別のリポジトリに公開する場合の手順です。

1. GitHubで新しいリポジトリを作り、名前を `fruit-catch`、公開範囲を **Public** にします。
2. リポジトリで **Add file → Upload files** を選びます。空のリポジトリでは **uploading an existing file** のリンクから進めます。
3. `fruit-catch` フォルダの「中身」をすべてアップロードします。`index.html` がリポジトリの一番上に見える状態にしてください。ZIPそのものはアップロードしません。
4. **Commit changes** で保存します。
5. **Settings → Pages** を開きます。
6. **Source** を **Deploy from a branch** にして、**Branch** を `main`、フォルダを `/(root)` に設定し、**Save** を押します。
7. 公開処理が終わるとPages画面にURLが出ます。一般的な形は `https://あなたのユーザー名.github.io/fruit-catch/` です。

公式説明：<https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site>

## iPhoneで遊ぶ

1. 公開できたURLをiPhoneのSafariで開きます。
2. iPhoneを縦向きにして「スタート」を押します。
3. 画面内を指でなぞるとカゴが左右に動きます。
4. 必要ならSafariの共有メニューから「ホーム画面に追加」を選ぶと、次回開きやすくなります。

PCの `127.0.0.1` というアドレスはiPhoneから開くための公開URLではありません。iPhoneへHTMLファイルだけ送る方法ではなく、公開URLを使ってください。ホーム画面への追加は、オフライン動作を保証する機能としては実装していません。

画面下のホームインジケーターと上部のセーフエリアを考慮しています。ゲーム画面ではページのスクロールを止め、図鑑やタイトルは小さな画面でもスクロールして全体を見られます。

## ゲームの仕様

| 難易度 | 時間 | 出現間隔 | 落下時間 | カゴ幅 |
|---|---|---|---|---|
| やさしい（初期設定） | 無制限 | 3秒 | 約5秒 | 40% |
| ふつう | 30秒 | 2秒 | 約4秒 | 32% |
| チャレンジ | 30秒 | 1秒 | 約3秒 | 26% |

カウントダウン後、最初の果物は約0.6秒で出ます。その後は上の間隔です。落下は経過秒数で計算し、描画が遅い場合は小さな時間単位に分けて衝突判定します。別のタブやアプリに移ってページが非表示になった間は停止します。

毎回の最初は必ずみかん、最初の5個は中央付近に落下します。最初の5個は抽選されたレア度内で未出現の果物を優先します。通常のレア度抽選はノーマル約67.67%・レア20%・スーパーレア9%・シークレット約3.33%（1/30）で、同じレア度の果物は均等です。最初のみかんと救済出現は通常抽選の例外です。シークレットは平均して約30個に1個の確率で、必ず30個ごとに出る方式ではありません。

3秒のカウントダウンを終えた時点を「1回プレイ」と数えます。10回目まで一度もシークレットが出なかった場合、10回目の2個目が必ずシャインマスカットになります。救済前に「おしまい」を押した場合だけ、最後にシークレットを出して落ち終わってから結果画面に移ります。この場合、終了まで約5〜6秒かかります。ブラウザ自体を強制的に閉じるとその場では出せませんが、未登場なら次回も救済を続けます。シークレットは登場しただけでは図鑑に登録されず、キャッチ成功が必要です。

## 保存について

図鑑の獲得数・プレイ回数・シークレット登場済みか・初回説明・音設定を `localStorage` に保存します。キャッチのたびに保存するので、結果画面に進む前に閉じても獲得分を保存します。

保存は端末・ブラウザ・公開URLのオリジンごとです。別の端末や別のブラウザとは共有しません。プライベートブラウズや履歴・サイトデータ削除で消える場合があります。保存できない場合は画面に案内を表示し、その回はメモリ上で遊べます。

## 動作確認と残っている確認事項

Windows Chromeの実ブラウザを自動操作し、開始・操作・当たり判定・難易度・保存・シークレット・縦画面サイズを確認しました。Chromeの終了後、同じプロファイルで起動し直して保存データが残ることも確認しています。音声更新後もこれらのテストは合格しています。

21種類の音声デコード、ユーザー操作後のWeb Audioの実行、果物名の再生開始、ミュート停止と設定保存も確認しました。実機iPhone、Safari/WebKitでの実行、実機スピーカーでの音量は未確認です。公開先はGitHub Pagesです。
## コンプリートと金メダル

15種類すべてをキャッチすると、金色のメダルを1枚獲得します。その場で図鑑の獲得数をすべて0に戻し、次の収集を始められます。メダルの累計枚数は保存され、タイトル・図鑑・結果画面に表示します。

お祝い画面の間は果物と残り時間が止まります。「つづけて あそぶ」で再開します。現在のプレイのキャッチ数や結果一覧は残ります。次にキャッチした果物は新しい図鑑に登録されます。もう一度15種類そろえるとメダルがさらに1枚増えます。

更新前にすでに15種類そろっていた場合も、次に開いたときに1枚授与し、図鑑をリセットします。メダル授与とリセットは一緒に自動保存し、再読み込みで重複して授与されないようにしています。
